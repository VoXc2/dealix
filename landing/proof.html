الحالة الافتراضية: لا Customer Proof عام

إذا لم يوجد Proof Pack حقيقي مكتمل المصدر والهوية والنطاق والتاريخ والموافقة وإذن النشر، تبقى الحالة Unknown/Blocked ولا نملأ الفراغ بأرقام Demo أو Synthetic أو Internal.

Evidence Levels

سلّم الأدلة L1 → L5

المستوى يصف قوة الدليل فقط. النشر العام يحتاج فوق ذلك إذن نشر صريحًا ومحددًا.

L1

Hypothesis / Internal Evidence

فرضية أو تحليل أو مسودة داخلية. ليست نتيجة عميل.

L2

Reviewed Evidence

مادة أو قرار تمت مراجعته وتوثيق مصدره، لكنه لا يثبت تسليمًا أو نتيجة وحده.

L3

Delivery / Outcome Evidence

دليل مرتبط بنفس الشركة والنطاق على إجراء أو تسليم أو Outcome محدد. لا يتحول تلقائيًا إلى قيمة مالية.

L4

Customer-Accepted Value Evidence

قيمة أو تحسن محدد له Baseline وطريقة قياس وقبول أو Evidence من نفس العميل، مع فصل التقدير عن القياس الفعلي.

L5

Verified Payment / Revenue Evidence

يتطلب سلسلة نفس الشركة: Scope معتمد + Payment request صادر فعليًا عند انطباقه + Receipt موثق + Reconciliation. وجود Proposal أو Invoice intent لا يكفي.

NO_FAKE_PROOF — Demo/Synthetic/Internal لا يصبح Customer Proof. Delivery وCustomer Value وPayment وRevenue وPublication Permission حالات منفصلة.

متى يمكن نشر Proof؟

1. نفس الشركة والنطاق

كل Claim يرتبط بمعرف شركة ونطاق Pilot/Delivery واضح، وليس بجمع أدلة من جهات مختلفة.

2. Evidence قابلة للتحقق

المصدر والتاريخ والـowner وطريقة القياس محفوظة، ويظهر مستوى الدليل الحقيقي دون ترقية.

3. لا تعارض مع الواقع

أي blocker في Payment أو Delivery أو Privacy أو Tenant أو Production يبقي Claim الأوسع Blocked.

4. إذن نشر مستقل

استخدام اسم العميل أو الشهادة أو تفاصيل قابلة للتعريف يحتاج Publication Consent مستقلًا؛ الموافقة على التسليم لا تعني الموافقة على التسويق.
