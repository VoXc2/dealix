# Dealix — Founder Master Path / Market-to-Delivery Master Plan

التاريخ: 2026-09-07

الحالة: دستور تشغيلي واستراتيجي مقترح داخل Company Machine الحالية. لا يمنح سلطة إرسال أو توقيع أو دمج أو نشر أو دفع أو تغيير Production من تلقاء نفسه.

## 0. القرار الأعلى

Dealix ليست شركة «AI Agents» ولا وكالة تطوير عامة بلا حدود. Dealix هي **AI Business Operating System + governed technology execution company** تأخذ احتياجًا حقيقيًا من السوق وتحوّله إلى قرار، حل مناسب، تسليم محكوم، ثم Proof يقبله العميل.

North Star:

`CASH_READY_AUTONOMOUS_DEALIX_COMPANY`

Optimization:

`Verified Economic Movement / Founder Minute / Cost / Risk`

القانون المركزي:

`RESEARCH WIDE -> SELECT NARROW -> DELIVER DEEPLY -> PROVE -> REPEAT -> PRODUCTIZE ONLY AFTER EVIDENCE`

ولا تتغير قوانين الحقيقة:

`Research != Relationship`

`Public Contact != Consent`

`Draft != Sent`

`Quote != Invoice != Payment`

`Delivery Activity != Customer Outcome`

`Synthetic Proof != Customer-Validated Proof`

## 2. Founder Master Path

هدف المؤسس ليس تشغيل الشركة يدويًا، بل إدارة **الهوية، رأس المال، السياسة، والعلاقات عالية الرافعة**.

### F0 — Trustable Company

المؤسس يتدخل فقط فيما يحتاج هوية أو أثرًا ماديًا:
- الكيان/الهوية القانونية والحسابات الرسمية.
- أسرار وحسابات مزودي الخدمة.
- Action-bound Production / DNS / DB / merge approvals.
- السياسة التجارية العليا وحدود المخاطر.

Company Machine تتولى reconciliation، الاختبارات، drafts، receipts، state tracking، وتحضير Action Packets.

### F1 — First Economic Proof

هدف المرحلة:

`1 Real Paid Engagement -> Delivered Scope -> Customer-Validated Proof`

المؤسس يشارك فقط عندما وجوده يزيد الثقة أو التعلم: أول Discovery، شريك استراتيجي، أو التزام تجاري نهائي.

### F2 — Repeatable Wedge

نكرر أفضل عرض/قطاع حتى نعرف:
- win rate الحقيقي؛
- زمن البيع؛
- collection days؛
- delivery hours؛
- direct cost؛
- gross/contribution margin؛
- rework؛
- customer acceptance؛
- founder minutes.

لا نوسع إلى قطاع جديد لمجرد وجود lead إذا الـwedge الحالي لم يصل بعد إلى Proof متكرر.

### F3 — Delegated Commercial Authority

بعد بيانات حقيقية، المؤسس يعتمد **policy bands** بدل كل صفقة:
- price/margin bands؛
- standard payment terms؛
- approved scope families؛
- discount ceiling؛
- SLA templates؛
- partner cost ceiling؛
- escalation triggers.

داخل الحدود: auto-prepare ثم auto-approve فقط إذا كانت السلطة الكنسية تسمح بذلك. خارجها: Founder Exception Approval.

### F4 — Delivery Network

Dealix تبني شبكة تنفيذ، لا payroll ضخمًا مبكرًا:
- internal capability؛
- qualified specialists؛
- implementation partners؛
- prime/subcontract routes؛
- white-label execution؛
- client-hosted delivery عندما يلزم.

كل شريك يحصل على due diligence + capability evidence + commercial terms + data/security boundaries + acceptance responsibilities.

### F5 — Recurring Revenue

بعد Proof:
- maintenance؛
- managed operations؛
- monitoring/reporting؛
- AI/knowledge runtime؛
- support/optimization؛
- usage or capacity plans عندما تكون قابلة للقياس.

لا يتحول المشروع إلى subscription قسرًا إذا العميل لا يحتاج تشغيلًا متكررًا.

### F6 — Productization / Scale

لا Productization قبل التكرار.

قاعدة عملية:
- مشكلة ظهرت مرة = custom learning.
- ظهرت 3 مرات = reusable pattern candidate.
- 5+ deliveries متشابهة = template/accelerator candidate.
- 10+ cycles مع اقتصاديات واضحة = product/SaaS evaluation.

المنتج الناتج يجب أن يقلل delivery cost/founder minutes أو يرفع margin/retention بشكل مثبت.

## 3. Portfolio Engine

الشركة تعمل في ثلاثة portfolios فقط:

### TRUST
Production / consent / approval / security / release identity / proof integrity.

### MONEY_NOW
Real interactions / qualified problems / diagnostics / discoveries / quotes / cash / delivery.

### COMPOUNDING
Official market intelligence / content from evidence / partners / reusable capabilities / learning.

الأوزان المقترحة:

إذا Trust غير Green:
`TRUST 30% / MONEY_NOW 50% / COMPOUNDING 20%`

إذا Trust Green:
`TRUST 10% / MONEY_NOW 70% / COMPOUNDING 20%`

Trust blocker لا يوقف الشركة كاملة؛ Money-Now وCompounding يستمران بما تسمح به السلطات.

1. **Contracting / Facilities Management**
   - project documents؛
   - RFIs / change orders؛

2. **Professional Services / SI / MSP / ERP / CRM / AI Implementers**
   - proposal-to-delivery leakage؛

3. **Manufacturing / Supply Chain Administrative Workflows**

Finance, energy, government and critical infrastructure stay in Radar, but initial route is bounded module / qualified partner / prime-subcontract where appropriate.

## 7. Pricing & Cash Law

لا يسعر Agent حسب Tokens فقط.

Cost model يشمل:
- engineering؛
- domain expertise؛
- partner cost؛
- cloud/model/API؛
- QA/security؛
- delivery/support؛
- licenses؛
- project management؛
- risk reserve؛
- working capital.

Internal cost floor:

`MinimumEconomicPrice = ExpectedDirectCost / (1 - TargetContributionMargin)`

هذه قيمة داخلية، وليست سعر السوق النهائي.

تعامل مع Cash كمسار مستقل:

`Quote -> Acceptance -> Invoice/Payment Request -> Verified Receipt -> Delivery Funding -> Collection -> Margin`.

Profit != Cash.

لا نشتري partner capacity أو cloud commitments الكبيرة على Invoice غير محصل بدون قرار تمويل واضح.

## 15. Kill / Stop Rules

STOP أو DEFER عندما:
- لا يوجد real problem evidence؛
- no buyer/owner path؛
- data access غير ممكن؛
- لا يمكن تعريف acceptance؛
- expected margin تحت الحد؛
- working-capital exposure غير مقبول؛
- liability أكبر من Dealix capacity؛
- يحتاج ترخيص/شريك غير متاح؛
- founder minutes تبقى عالية بعد محاولات التحسين؛
- العميل يريد guarantee غير قابلة للدفاع؛
- project is bespoke once-only with no economics/strategic proof؛
- customer refuses required data/security/acceptance controls.

## 16. 90-Day Master Plan

### Days 0–14 — Converge + Prove
- close only Trust blockers that prevent controlled real work؛
- exact-head source/runtime proof؛
- capability register؛
- three wedge-specific Diagnostic/Outcome Sprint templates؛
- partner shortlist by capability gap؛

### Days 15–30 — First Cash Path
- advance qualified interactions to diagnostics/discovery؛
- create customer-specific quotes؛
- start only when payment/start authority is verified؛
- capture actual delivery economics from day one.

### Days 31–60 — Repeat / Margin
- repeat best wedge؛
- reduce delivery variance؛
- standardize artifacts؛
- convert successful outcomes into permissioned proof؛
- test maintenance/managed-service expansion where justified.

### Days 61–90 — Vertical Depth
- select 1–2 verticals by actual win/margin/collection/repeatability evidence؛
- deepen partner ecosystem؛
- delegate standard commercial policy bands؛
- create accelerators only from repeated paid patterns؛
- reduce Founder Minutes materially.
