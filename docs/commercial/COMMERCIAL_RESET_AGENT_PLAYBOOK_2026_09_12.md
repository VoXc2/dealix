## 2. Commercial Reset

Dealix sells governed improvement to measurable business workflows, not an arbitrary number of agents or generic AI features.

Positioning:

`Dealix — Saudi AI Business Operating System`

Mechanism:

`Assess -> Decide -> Automate -> Govern -> Prove`

Commercial path:

`Market Signal -> Evidence -> Relationship State -> Qualified Problem -> Free Diagnostic -> Qualified Discovery -> Solution Design -> Customer-Specific Proposal -> Negotiation Preparation -> Pilot Decision -> Invoice -> Verified Payment -> Governed Delivery -> Customer-Validated Proof -> Expansion / Referral -> Productization`

Every diagnostic remains free and card-free unless newer explicit authority supersedes that rule.

Public fixed prices are not authority. Named-customer commercial terms are customer-specific after qualified discovery.

## 3. Agentic Holding execution model

Dealix is one Company Machine expressed as a governed **Agentic Holding**:

```text
Dealix Group
  -> Shared Agent Services
  -> Sector Companies
  -> Arm Pods
  -> Bounded Specialists
```

The old `exactly five permanent agents` invariant is deprecated.

Legacy owner names may remain in compatibility components:

| Legacy alias | Holding role |

These are aliases, not the complete logical-agent fleet.

No sector company or arm gets its own Company Brain, CRM, scheduler, model router, Approval Center, Proof Ledger or Economic Truth system.

## 14. Pricing preparation

Public fixed-price authority remains disabled.

Internal quote preparation uses:

`Price = max(Cost Floor, Market Floor, Value-Adjusted Floor)`

Then adjust for scope, integrations, data complexity, security/regulatory load, urgency, support/SLA, customization, expected value, reuse/proof value and margin/capacity risk.

Internal reference bands in the reset config are guardrails only. They are not public tariff authority and are not doctrine. Refresh current market, value and delivery-cost evidence before every material named-customer quote.

## 15. Email draft factory

Customer-facing drafts are only appropriate for:

- real inbound;
- warm introduction;
- documented opt-in;
- customer-requested follow-up.

Draft structure:

`WHY THEM -> WHY NOW -> EVIDENCE-BOUND INSIGHT -> PROBLEM HYPOTHESIS -> VALUE HYPOTHESIS -> ONE CTA`

Default CTA: free diagnostic or short discovery.

Default state: `safe_to_send=false`.

Research-only accounts never become a send queue merely because public contact data exists.

## 19. Hermes / OpenCode / model portfolio

Hermes remains the orchestration fabric.

OpenCode is preferred for engineering, code review, repo analysis, refactoring, tests, web/API work, integrations, automation, technical research and other high-value execution where it materially improves results.

Deterministic checks remain first for health, monitoring, fingerprints and scheduler audits. Local/private models are preferred for bounded low-risk extraction/classification. Use the cheapest adequate model and escalate only when acceptance requires it. No uncontrolled paid spill.

## 20. Compliance and trust

Translate regulation into operational controls, not unsupported marketing claims.

Examples:

- PDPL -> data/consent/retention/access/vendor/model-routing controls;
- NCA -> control mapping/readiness/evidence;
- ZATCA -> technical integration/readiness;
- SAMA -> supervised-market awareness and partner-first execution.

No certification or regulator-endorsement claim without exact evidence.

## 21. Authority

Autonomous internal authority:

- L0 Observe
- L1 Analyze
- L2 Draft
- L3 Internal Execute
- L4 Repository Execute

Material external effects remain exact-action gated, including live customer send, public publish, binding commercial/legal commitment, invoice/payment/spend, tender submission, protected-main merge where governed, production deploy/cutover, DNS, production DB/schema mutation, secrets/keys, firewall/root changes and destructive provider/account operations.

If one material action is blocked, create one bounded approval packet and continue safe work.

## 22. Proof and learning

`Activity != Delivery != Payment != Revenue != Customer Value != Publication Permission`

Only productize after repeatable conversion, delivery and proof evidence.
