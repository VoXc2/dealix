# Dealix Visual Direction

## Objective

Make Dealix look like a **Saudi enterprise operating system**: calm, precise, structured, trustworthy and evidence-led.

The visual system should help a buyer understand operating state, risk, decisions, controls and proof. Decoration is secondary.

## Active public implementation reference

Read `docs/brand/BRAND_AUTHORITY_MAP.md`.

Until an explicitly approved migration replaces it, the canonical `landing/index.html` implementation is the active public visual reference.

Verified active language in that source includes:
- Ink Navy `#0F172A`
- Deep Teal `#164E63`
- Signal Cyan `#22D3EE`
- Cloud / near-white `#F8FAFC`
- Slate neutrals
- Arabic: `IBM Plex Sans Arabic`
- Latin: `Inter`

Historical Navy/Gold, Emerald/Gold and Saudi-Green/Gold files are reference/history, not permission for new cross-channel drift.

## Color roles

### Ink Navy
Executive command, high-authority surfaces, dark proof panels, navigation or primary contrast.

### Deep Teal
Operating depth, secondary command states, supporting surfaces and diagrams.

### Signal Cyan
Use sparingly for signals, active states, key data points, CTAs and proof/decision emphasis. It should feel functional, not neon-decorative.

### Cloud / White / Slate
Primary reading surfaces, whitespace, hierarchy, neutral evidence states and long-form content.

### Semantic colors
Success, warning and danger must remain semantic status colors. They do not become campaign palettes.

## Typography

### Arabic
`IBM Plex Sans Arabic` is the preferred active public family.

### Latin
`Inter` is the preferred active public family.

### Data / code
Use a restrained monospace stack for evidence IDs, status codes, technical labels and machine-readable concepts.

Arabic and English must preserve equivalent hierarchy and authority. Arabic is not a smaller secondary caption layer.

## Visual grammar

Prioritize:
- executive command cards;
- evidence cards;
- before / after operating-state diagrams where evidence supports them;
- `signal -> priority -> approval -> action -> outcome -> proof` flows;
- buying-group / decision maps;
- real product/process screenshots with sensitive data removed;
- explicit state labels such as `DRAFT`, `APPROVAL_REQUIRED`, `VERIFIED`, `BLOCKED`;
- clean grids, strong spacing and clear reading order;
- restrained line icons and diagrams;
- functional motion only when it explains a state transition.

## Proof visualization

Every proof visual must state or make clear its class:
- internal capability;
- synthetic/demo;
- runtime/production;
- customer delivery;
- customer outcome.

Do not use visual polish to make weak evidence look stronger than it is.

## Saudi-first visual expression

Use Saudi context when it improves comprehension or relevance. Avoid:
- generic skyline wallpaper;
- decorative flag motifs on every asset;
- government emblems without authority;
- stereotyped desert imagery unrelated to the message.

Premium Saudi expression should come primarily from typography, restraint, local language quality, business relevance and execution quality.

## Photography and imagery

Prefer:
- authentic founder/operator photography;
- real event/field observations when permitted;
- real workflow/product screenshots;
- diagrams and evidence visuals.

Avoid:
- generic handshakes;
- robot heads;
- glowing AI brains;
- fake command-center screens;
- fabricated KPI dashboards;
- unlicensed or unsupported customer/logo walls.

## Motion/video

Dealix video should feel like an operating briefing, not an AI spectacle.

Preferred:
- one problem per short video;
- restrained animated system maps;
- screen recordings with clear callouts;
- evidence/decision cards;
- Arabic captions as a first-class layout component;
- deliberate pauses and readable information density.

Avoid constant particle effects, cyberpunk grids, generic neural-network loops and fast motion that reduces comprehension.

## Asset families

Use one system across:
- website;
- company profile;
- proposals;
- executive decks;
- proof packs;
- Founder LinkedIn visuals;
- company social content;
- event one-pagers / QR cards;
- video thumbnails;
- trust/security material.

Do not create a new palette for every platform or product module.

## Canva / renderer rule

Canva and other renderers implement versioned templates; they do not define the identity.

A reusable template should record at minimum:
- brand version;
- template version;
- channel;
- target buying-group role;
- claim/evidence requirements;
- safe areas / aspect ratio;
- CTA slot;
- lifecycle state.

## Accessibility

- maintain readable contrast;
- avoid encoding status by color alone;
- preserve Arabic legibility at mobile sizes;
- respect reduced-motion preferences where applicable;
- do not shrink evidence caveats below practical reading size.

## Acceptance checklist

Before public use:
1. Is the visual using the active brand system rather than a historical palette?
2. Is the buyer problem or decision clear before decoration?
3. Are any data/outcome visuals backed by the right evidence class?
4. Is Arabic visually first-class?
5. Does Signal Cyan remain functional rather than decorative?
6. Are no fake logos, dashboards, testimonials or government signals present?
7. Could this asset sit beside the current Dealix website without looking like a different company?
