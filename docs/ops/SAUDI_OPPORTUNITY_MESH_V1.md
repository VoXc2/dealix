# Dealix Saudi Opportunity Mesh V1

## Purpose

Operate one Saudi market-to-delivery machine that searches widely across official demand, economic triggers, supplier networks, projects, partnerships, events and public-company signals, then selects narrowly and delivers deeply.

This document does **not** create another CRM, Company Brain, scheduler, agent fleet or opportunity graph. It binds the expanded market-source registry to the existing Dealix Company Machine and Market-to-Delivery path.

## Demand grades

- **D4** — explicit live tender, RFQ/RFP, paid implementation request or direct commercial request.
- **D3** — customer-confirmed problem or active verified discovery.
- **D2** — fresh economic trigger with source evidence: expansion, regulation, project, funding, supplier-access change, award, system change or current procurement ecosystem.
- **D1** — directory, sector hypothesis, event, broad ecosystem signal or background research.

A higher demand grade does not create consent, relationship, award, qualification or authority.

The machine may add a source only through the existing source registry owner and must preserve provenance, freshness, lane, access mode, polling hint, agent route and forbidden-inference rules.

## WIP and selection law

Research breadth can be large; execution breadth cannot.

```text
EXECUTIVE_TOP_ACTIONS_MAX=3
COMMERCIAL_DEEP_WIP_MAX=10
CUSTOMER_DIAGNOSTICS_MAX=3
LIVE_PROJECT_CELLS_MAX=2
MATERIAL_APPROVAL_PACKETS_MAX=1
ACTIVE_GTM_WEDGES_MAX=3
```

Use the full source mesh for discovery, but move only the strongest evidence-backed opportunities into deep work.

## Project execution routes

Every qualified opportunity must select one primary delivery route:

- `BUILD_DIRECT`
- `CONFIGURE_ADAPT`
- `INTEGRATE_EXISTING_PRODUCT`
- `QUALIFIED_PARTNER`
- `SUBCONTRACT_PACKAGE`
- `DISCLOSED_REFERRAL`
- `DECLINE_DEFER`

Do not sell a capability route that has not passed feasibility, authority and evidence checks.

## Supplier/tender path

```text
D4/RFQ/RFP/TENDER
→ requirement extraction
→ eligibility/classification
→ mandatory documents
→ deadline/freshness
→ technical capability fit
→ prime vs partner vs subcontract
→ delivery owner + specialist gaps
→ commercial economics
→ legal/guarantee/payment risk
→ acceptance/proof plan
→ BID / PARTNER-BID / NO-BID recommendation
→ exact L5 packet for any submission or commitment
```

No booklet purchase, guarantee, live price submission, bid, contract or external commitment is authorized by research alone.

## Supplier readiness path

For gated supplier networks, Dealix prepares internally:

- legal/company identity facts
- evidence-backed capability matrix
- service categories
- delivery routes and subcontract boundaries
- security/data posture
- acceptance/proof model
- local-content facts only when verified
- relevant certifications only when actually held
- reference/proof status without synthetic customer claims
- qualification gaps and missing documents

Registration remains a separate external/material action where applicable.

## Truth Firewall

`Research != Relationship`

`Public Contact != Consent`

`Signal != Opportunity`

`Event Presence != Buyer Intent`

`Supplier Registration != Tender Invitation`

`Tender Publication != Dealix Eligibility`

`Draft != Sent`

`Quote != Invoice`

`Invoice != Payment`

`Internal Proof != Customer-Validated Proof`

`Model Output != Authority`

`Unknown = UNKNOWN_NOT_EVIDENCE_BACKED`

## Material authority

The following remain exact-action-bound L5:

- tender/RFQ/RFP submission
- supplier registration when it creates external commitments or legal attestations
- external customer/partner send
- binding quote
- contract/tender/legal commitment
- paid spend/guarantee/payment/refund
- production mutation
- customer-system release

The bots may research, analyze, draft, qualify, design, test and prepare proof autonomously within L0-L4. They may not self-authorize material effects.
